# C-0001. Claude는 클라이언트 영역에서 구현자가 아니라 학습 가이더로 일한다

- 상태: 채택
- 날짜: 2026-10-13
- 결정한 사람: @<CLIENT_OWNER>
- 영역: client

> 클라이언트 ADR은 루트 `docs/decisions/`와 번호가 겹치지 않도록 `C-NNNN`으로 부른다.

## 맥락

- 클라이언트 담당자의 목적은 Tabiji 완성과 함께 **Kotlin·Compose Multiplatform을 기초부터 손으로 익히는 것**이다
- 담당자는 ROS 2·C++/Qt6 Widgets 경험이 있지만 Kotlin은 처음에 가깝다
- Claude Code는 화면 하나쯤은 금방 구현할 수 있다. 그대로 맡기면 앱은 빨리 생기지만 담당자는 코드를 읽기만 하게 되고, 막혔을 때 스스로 진단할 수 없다
- 여러 머신·세션을 오가며 진행하므로 "어디까지 했는지"가 레포 안에 남아야 한다

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. Claude가 구현, 사용자는 리뷰 | 가장 빠름 | 학습 효과가 낮다. 리뷰할 기준 자체가 없다 |
| B. Claude 없이 혼자 공부 | 온전히 내 것 | 막힐 때 시간 손실이 크다. 설계 실수를 늦게 알아챈다 |
| **C. Claude는 가이드·리뷰·진단, 코드는 사용자가** | 손으로 쓰며 배우고, 막히면 원인을 같이 찾는다 | 진행이 느리다. Claude가 "그냥 짜 주는" 유혹을 규칙으로 막아야 한다 |

## 결정

**C를 택한다.** 구체 규칙은 [`client/CLAUDE.md`](../../CLAUDE.md) 1절이 원본이다.

- 기본: 단계 가이드 → 사용자 구현 → 진단 → 다음 단계. 한 번에 한 단계
- 스니펫은 개념을 보여 주는 10줄 안팎까지. 전체 구현은 사용자가 명시적으로 요청할 때만
- 빌드·실행·테스트는 사용자가 직접 돌리고 결과를 붙여넣는다. 오류를 직접 읽는 것도 학습이다
- 빌드 설정(Gradle)·CI는 학습 대상이 아니므로 설명 후 Claude가 수정할 수 있다
- 진행 상황은 `client/docs/roadmap.md`(현재 위치)와 `client/docs/worklog.md`(세션 메모)에 남긴다
- 가이드는 단계를 시작할 때 하나씩만 쓴다. 미리 써 두면 앞 단계에서 배운 것과 어긋난다

## 결과

- 쉬워지는 것: 담당자가 모든 코드를 설명할 수 있다. 진단 능력이 쌓인다. 세션이 끊겨도 worklog로 이어 간다
- 감수할 것: 기능 완성 속도가 느리다. 서버·AI 팀과 일정이 엇갈리면 해당 단계만 "대신 해줘"로 예외 처리한다
- 다시 검토할 조건: Phase B 완료 후, 또는 마감이 있는 데모 일정이 잡힐 때
