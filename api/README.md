# api/

클라이언트↔서버 REST 계약을 두는 곳. `openapi.yaml`(OpenAPI 3.1)이 이 폴더에 들어온다. **클라이언트가 외부와 통신하는 경로는 이 계약과 지도 타일 두 갈래뿐이다.**

## 파일

| 파일 | 상태 |
| --- | --- |
| `openapi.yaml` | 아직 없음. 서버 담당이 초안을 쓰고 클라이언트 담당이 리뷰한다 (클라이언트 Phase D 전까지) |

## 계약 변경 규칙

1. 계약 변경은 **`api/` 단독 PR**로 먼저 올린다. 브랜치 `api/<type>-<slug>` (예: `api/feat-leg-confidence`), 커밋 `feat(api): ...`
2. CODEOWNERS에 따라 **클라이언트·서버 담당 둘 다** 리뷰한다. 셀프 머지 금지
3. PR 설명에 쓸 것: 무엇이 바뀌는지, 하위 호환 여부, 양쪽 구현 계획(어느 PR에서 따라갈지)
4. **깨지는 변경(breaking change)** — 필드 삭제·이름 변경·타입 변경·필수화 — 은 PR 제목에 `!`를 붙이고(`feat(api)!: ...`), 이전 필드를 한동안 유지할지 합의한다
5. 필드 추가는 선택(optional)으로 넣는다. 클라이언트는 모르는 필드를 무시한다
6. 계약 PR이 머지된 뒤에 서버·클라이언트 구현 PR을 각자 올린다
