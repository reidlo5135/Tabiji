# 10 · 인트로 (사계절) — 계절 이미지 4장 + Compose 드로잉 로고·메뉴

**v1.1에서 구조가 바뀌었다.** 벡터 레이어 합성(구버전) 대신 **팀이 제작한 계절별 일러스트 4장**을 그대로 쓰고, 중앙의 로고·메뉴는 배경 박스 없이 **Compose에서 직접 그린다**. 원본: `source/intro_desktop_light.html`, `source/intro_phone_light.html` (수치가 이미지와 다르면 source가 정답, 1px = 1dp).

- 패키지의 webp는 **긴 변 2048 · 품질 85로 최적화한 번들용**(장당 330~430KB)이다. 원본 PNG(장당 7~8MB)는 패키지 용량 때문에 제외 — 팀 원본 보관소(이미지를 만든 쪽)에 있고, 더 큰 해상도가 필요해지면 같은 파이프라인(리사이즈+WebP)으로 다시 뽑는다.
- 이미지는 팀 제공 에셋이며 제3자 캐릭터가 포함되어 있다. 배포 시 권리 처리와 교체 판단은 팀 몫이고, 교체 시 **같은 파일명으로 바꿔 넣기만 하면 된다** (코드는 파일명만 참조).
- 배치: Android는 `drawable-nodpi` 또는 Compose Multiplatform 공통 리소스(`composeResources/drawable/`), Desktop도 같은 공통 리소스로 충분하다.

## 레이아웃과 "fit-in-view" 규칙 (비율이 달라도 딱 맞게)

네 이미지의 비율이 사분면 비율과 다르므로, **모든 사분면은 다음 한 가지 규칙**으로 통일한다:

> **ContentScale.Crop + 지정 Alignment(기본 Center)** — 이미지를 왜곡 없이 확대·축소해 사분면을 가득 채우고, 넘치는 부분은 잘라낸다. 레터박스(여백)와 늘어남(stretch)은 금지.

```kotlin
Image(
    painter = painterResource(Res.drawable.intro_spring),
    contentDescription = "봄 풍경",
    contentScale = ContentScale.Crop,
    alignment = BiasAlignment(0f, season.focusY),   // 아래 표의 크롭 기준점
    modifier = Modifier.fillMaxSize().clipToBounds(),
)
```

크롭 기준점(focus): 비율 차이로 잘려 나가는 방향에서 **주요 피사체가 남도록** 세로 바이어스를 준다. CSS `object-position`의 y%와 Compose `BiasAlignment.verticalBias`(−1..1) 환산은 `bias = (y% − 50) / 50`.

| 계절 | Desktop(비율 1.6) 크롭 | Phone(비율 1.85) 크롭 | focus y% | verticalBias |
| --- | --- | --- | --- | --- |
| 봄 | 좌우 ~11% 잘림 | 세로 ~3% 잘림 | 50% | 0f |
| 여름 | 좌우 ~11% 잘림 | 세로 ~3% 잘림 | 50% | 0f |
| 가을 | 상하 ~16% 잘림 | 상하 ~28% 잘림 | 55% (Phone 58%) | +0.1f (+0.16f) |
| 겨울 | 상하 ~16% 잘림 | 상하 ~28% 잘림 | 55% (Phone 58%) | +0.1f (+0.16f) |

가을·겨울은 인물이 화면 아래쪽에 있어 아래로 바이어스를 줬다. 새 이미지로 교체할 때는 **중앙 1.6:1(Phone 기준이면 1.85:1) 영역 안에 핵심 피사체**가 들어오게 만들면 어떤 비율이든 안전하다.

### 배치

- **Desktop 1440×900(가변)**: 2×2 그리드 — 좌상 봄 · 우상 여름 · 좌하 가을 · 우하 겨울. 각 셀은 위 규칙의 `Image` 하나. 경계는 이미지끼리 맞닿는 하드 엣지 (하이즈/블렌딩 없음 — 네 장이 각자 완성된 장면이므로).
- **Phone 390×844**: 세로 4단 (봄→여름→가을→겨울), 각 단 211dp. 같은 규칙.
- 창 비율이 바뀌어도 규칙은 동일 — 셀 크기가 변하면 crop 범위만 달라진다.

## 중앙 로고·메뉴 스택 (Compose에서 직접 그림, 배경 박스 없음)

화면 정중앙에 `Column(horizontalAlignment = CenterHorizontally)`:

| 요소 | 스펙 |
| --- | --- |
| 워드마크 "Tabiji" | Sora Bold, Desktop 56sp/64 (Phone 44/52), 자간 −0.02em, `#FFFFFF`. 그림자 2겹: `(0, 2dp, blur 4dp, #0E1621 50%)` + `(0, 8dp, blur 28dp, #0E1621 55%)` — Compose `TextStyle.shadow`는 1개만 받으므로 같은 텍스트를 겹쳐 그리거나 넓은 쪽 하나만 사용 |
| 부제 "여행(旅路) 도우미" | 6dp(Phone 4) 아래 · Pretendard 600 16sp(14) · `#FFFFFF 95%` · 자간 0.12em · 같은 그림자 |
| 버튼 스택 | 28dp(Phone 24) 아래 · 폭 340dp(Phone 300) · 세로 나열 gap 10 · 스택 전체 `drop-shadow(0 10dp 24dp #0E1621 28%)` |

버튼 행 (아이콘 좌 · 제목+부제 · 쉐브론 우):

1. **시작하기** — 높이 56 · `chamferShape(12, 8)` · `accent.sky` 채움 + 상단 1dp 하이라이트 55% · 글자 `accent.on` (제목 15/700, 부제 "새 여행 일정 만들기" 11/500 @78%) · 장소 아이콘 22
2. **내 여행** — 높이 52 · 모서리 12 · `surface.glass`(블러 16, 불가 시 `surface.glass.solid`) + 테두리 1 `line.subtle` · 제목 14/600 `text.primary`, 부제 "저장된 일정 보기" 11 `text.secondary` · 달력 아이콘 20 `accent.text`
3. **설정** — 내 여행과 동일 · 부제 "테마 · 언어 · 데이터" · 기어 아이콘

로고·부제는 표면이 없으므로 대비가 이미지에 따라 변한다 — **그림자가 가독성을 보장**하는 구조이고, 버튼은 자체 표면이 있어 기존 대비 기준을 그대로 만족한다.

## 파티클 오버레이 (이미지 위, 추후 애니메이션의 1단계)

이미지가 교체되어도 파티클은 사분면 위에 오버레이로 유지한다 (`Canvas` + `withFrameNanos`, seed 고정). 수치는 구버전과 동일:

| 계절 | 모양 | 수(Desktop/Phone) | 속도 |
| --- | --- | --- | --- |
| 봄 | 벚꽃잎 7–10dp | 8 / 4 | 낙하 9–12s, x +40dp, 회전 0→300° |
| 여름 | 반사광 막대 + 구름 흐름은 이미지에 있으므로 **반짝임 6개만** | 6 / 3 | 불투명도 0.3↔0.9, 2–3s 사인 |
| 가을 | 낙엽 10–12dp | 8 / 4 | 낙하 9.5–12s, x +40dp, 회전 |
| 겨울 | 눈송이 5–8dp | 12 / 6 | 낙하 11–15s, x −30dp |

패럴랙스: 이미지가 단일 레이어가 됐으므로 **이미지 ±4dp, 파티클 ±8dp** 2단으로 축소 적용 (포인터/자이로, 240ms 감속). 이것이 "추후 계절별 애니메이션"의 기반 — 이후 단계에서 이미지를 레이어 분리하거나 시네마그래프식 부분 애니메이션으로 확장한다.

## 시퀀스 (storyboard.png · 타이밍 동일)

| 시간 | 동작 |
| --- | --- |
| 0–600ms | 봄→여름→가을→겨울 순차 페이드인 (각 300ms, stagger 150) |
| 600–1200ms | 로고·메뉴 스택 12dp 상승 + alpha 0→1 (600ms 감속), 워드마크→부제→버튼 순 80ms 스태거 |
| 1200ms~ | 루프: 파티클 + 패럴랙스 |
| 호버/터치 | 해당 사분면 밝기 +8%, 나머지 −6% (120ms) — `ColorMatrix` 또는 흰/검 오버레이 알파 |
| 동작 줄이기 | 전환 0ms, 파티클·패럴랙스 끔, 정지 프레임 |

## 다크 테마

이미지 위에 `#0E1621` 세로 그라데이션 62%→50% 오버레이 한 장 (`opacity.introNightOverlay`). 메뉴 버튼 표면은 다크 토큰을 따른다. 별도 다크용 이미지는 만들지 않는다.
