# design/

디자인 요청과 결과물(핸드오프)을 두는 곳.

```
design/
├── requests/        # 디자인 요청서 (누구나 작성)
└── handoff/
    └── handoff-vN/  # 디자이너가 넘겨 준 결과 스냅샷
        ├── README.md     # 이 버전에서 바뀐 화면·토큰 요약
        ├── PROMPT.md     # (있으면) 구현 지시서
        ├── images/       # 화면 이미지
        └── source/       # 원본 수치 (토큰, 스펙). 이미지와 다르면 이게 정답
```

## 운용 규칙

1. **요청**: 새 화면이나 변경이 필요하면 `design/requests/YYYY-MM-DD-<slug>.md`를 쓰고 PR(`design/docs-<slug>`)을 연다. 이슈 템플릿 "Design request"로 시작해도 된다
   - 요청서에 쓸 것: 화면 이름, 목적, 들어갈 데이터, 상태(빈·로딩·오류), 참고 이미지, 마감
2. **핸드오프**: 결과는 새 폴더 `design/handoff/handoff-vN/`으로 받는다. **N은 이전보다 하나 큰 정수**
3. **덮어쓰기 규칙**: 새 버전의 문서가 이전 버전의 해당 절을 덮어쓴다. 언급되지 않은 부분은 이전 버전이 유효하다
4. **수치 우선순위**: 이미지와 수치가 다르면 `source/`의 원본이 정답이다
5. **스냅샷 불변**: 한 번 머지된 `handoff-vN/`은 수정하지 않는다. 고칠 게 있으면 `handoff-v(N+1)`을 만든다
6. **IP 주의**: 타사 캐릭터·로고·UI 프레임·전용 폰트는 넣지 않는다. 폰트는 OFL 등 재배포 가능한 라이선스만, 라이선스 파일을 같이 둔다
7. 클라이언트는 `PROMPT.md`를 그대로 실행하지 않고 `client/docs/roadmap.md` 단계로 재구성해 쓴다 (`client/CLAUDE.md` 참조)
